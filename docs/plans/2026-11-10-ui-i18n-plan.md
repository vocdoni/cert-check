# Testing UI in English, Spanish and Catalan — plan (Bounded)

Base: `main` at `6b5e65c` (v0.1.2). Branch: `feat/ui-i18n`.
Scope: `testui/web` only (static UI, embed, tests, devserver browser test) plus `testui/README.md`.

## Spec

### Goal

The testing UI (cert-check.vocdoni.dev) speaks English, Spanish and Catalan. It picks the
language from the browser and offers a language selector.

### Owner decisions (2026-11-10)

- **Register.** Spanish and Catalan address the user formally: *usted* / *vostè*. For example,
  "Elija su certificado" and "Triï el seu certificat".
- **Language resolution order:**
  1. the user's saved choice;
  2. the browser's preferred languages, in order. The first match wins: `ca*` → Catalan, `es*` →
     Spanish, `en*` → English, and the other languages of Spain (`gl*`, `eu*`, `ast*`, `an*`,
     `oc*`) → Spanish;
  3. Spanish when nothing matches.

### Acceptance criteria

1. **Coverage.** Every piece of text the UI renders exists in `en`, `es` and `ca`:
   - the static text of `index.html` (title, eyebrows, headings, ledes, labels, hints, buttons,
     notes, notices, `<summary>`);
   - the client messages and guidance tables;
   - the working-view texts, success-view row labels and fallback values;
   - copy-button feedback, `aria-live` status messages, and the `showFatal` panel.

   A test checks that the three dictionaries have exactly the same keys and that no value is
   empty.
2. **Server error codes.** The UI shows its own localized message for every error code the API
   can return. That covers every key of the `messages` table in
   `testui/internal/server/api.go`, the `ErrorCode`s in the root `types.go`, and the client
   codes. The server's English `message` is used only for a code the UI does not know. A test
   checks that every server and library code has an entry in all three languages.
3. **Language selector.** A selector sits in the site header and lists the languages by their own
   names: "English", "Español", "Català".
   - It has an accessible label.
   - Choosing a language re-renders the current view in place, with no reload. A shown result,
     error, guidance or diagnostic state must survive the switch.
   - It sets `<html lang>` and `document.title`.
   - It saves the choice in `localStorage` (`certcheck.lang`). Storage errors are tolerated, as
     the existing session-storage helpers do.
4. **Automatic detection.** With no saved choice, the language follows the resolution order in
   the owner decisions, using `navigator.languages` and falling back to `navigator.language`.
5. **What is not translated:**
   - Provider names and descriptions from `/api/v1/providers` are official names and are shown
     as served.
     - Exception: the DNIe entry's English qualifier ("requires card reader" in the name, and
       the English clause in its description) is localized on the client, keyed by provider id
       `dnie`.
   - The diagnostic report stays in English, because it goes to Vocdoni support, and
     `TestReportGolden` stays unchanged. A localized one-line note next to the report says so.
   - `<noscript>` holds one short sentence in each of the three languages.
6. **Unchanged:**
   - The CSP: no inline script or style, no `eval`. A new script is a same-origin file such as
     `static/i18n.js`, loaded with `defer` before `app.js`, or the strings live in `app.js`.
   - No new libraries or Go modules, and no build step.
   - Production response headers, the API, and every testui golden.
   - The diagnostic report bytes.
7. **Safety.** Translations are inserted with `textContent` only, keeping the
   `TestNoUnsafeDOM` property. Language codes from storage or the browser are validated against
   the three supported codes. Lookups use the own-property helper (`lookup`), never a plain
   `table[key]`.
8. **Older browsers.** The new code uses nothing newer than the R14.1 baseline
   (Safari 15 / Chrome 90 / Firefox 90), and the error paths keep working.
9. **Tests:**
   - Static tests: dictionary parity (AC1); code coverage (AC2); the required text in each
     language (extend `TestRequiredText`); the embedded-file list updated.
   - `TestBrowser` (`-tags browser`) gains cases run with Chrome `--lang=es-ES`,
     `--lang=ca-ES` and `--lang=fr-FR`, which must show Spanish. Existing cases set English
     explicitly so they stay deterministic.
   - The selector behaviour (switch on the error and success views, persistence across reload,
     `<html lang>`) is checked with Playwright against the devserver. Paste the evidence in the
     report.
10. **Docs.** `testui/README.md` describes the languages, the detection order, the selector and
    the stored key.

### Non-goals

- Translating the API, the library or the diagnostic report.
- Translating provider data beyond the DNIe qualifier.
- Languages other than these three.

## Global constraints

The constraints in `.delivery/2026-11-01-security-audit/fix-common.md` apply:
- test-first;
- minimal diffs;
- no new dependencies;
- goldens are byte contracts;
- `TMPDIR`/`GOTMPDIR` under `~/.cache/cert-check`, never `/tmp`;
- commits `type(scope): lowercase`, with explicit paths and **no AI attribution or `Co-Authored-By`
  trailers**;
- never push.

Keep the existing look. The selector reuses the existing select styling, scaled for the header.

## Review focus

- No unsafe DOM sink is introduced.
- The selector re-renders without losing state.
- Detection order and fallback.
- Translation quality: natural, formal and consistent terminology (certificado / certificat,
  lector de tarjetas / lector de targetes, revocado / revocat, emisor / emissor), and no English
  left in es/ca.
- No regression on older browsers.
